Features

🔍 Vulnerability Scanning

Every component matched against OSV.dev across 15 ecosystems (npm, PyPI, Maven, Go, NuGet, RubyGems, crates.io, Debian, RHEL, Alpine, and more), enriched with CVSS v3.1 and EPSS exploit-probability scores.

🔒 Secrets Detection

Gitleaks scans container image filesystems and repository working trees for exposed credentials — all findings rated CRITICAL, since a leaked secret is immediately exploitable.

🤖 AI Compliance (flagship)

Turns your SBOM into a regulator-ready AI/ML risk view — EU AI Act tiering, OWASP LLM Top 10, MITRE ATLAS, NIST AI RMF, GDPR data-residency — entirely from static analysis, zero LLM calls.

📦 Three Ways to Scan

Upload a CycloneDX/SPDX SBOM, point at a container image, or give it a Git repository URL. Image and repo scans also generate the SBOM for you and run secrets detection.

🔌 Built for CI/CD

A full REST API with scoped read/write API tokens, a ready-to-use GitLab CI template, and VEX import/export for triage data that travels with your pipeline.

⚡ Zero-Config Quick Start

One docker compose up and you're in — no .env file required. Secrets auto-generate safely on first boot; harden them before exposing the instance publicly.

☸️ Kubernetes & OpenShift Ready

A production Helm chart ships in the repo — non-root images, OpenShift restricted-v2 SCC compatible out of the box, no special SCC grant needed.

🆓 Free & Self-Hosted

Quick Start

  1. 1. Get the compose file

    curl -O https://raw.githubusercontent.com/marius-cornaciu/sbom-shield-website/main/docker-compose.yml

    No .env needed to try it out — safe defaults kick in automatically.

  2. 2. Start the stack

    docker compose up -d

    Boots PostgreSQL, Redis, the API, two Celery workers, and the frontend — pulling the images below automatically.

    docker.io/mcmwhfysec/sbom-shield-backend:latest
docker.io/mcmwhfysec/sbom-shield-frontend:latest

    Current release 1.6.6 — multi-arch (amd64 + arm64), Cosign-signed and SBOM-attested. Pin :1.6.6 for reproducible deploys; :latest moves with each release.

  3. 3. Log in

    Open http://localhost:9000 and log in with admin / admin — you'll be asked to set a real password immediately. Set SECRET_KEY, POSTGRES_PASSWORD, and ADMIN_PASSWORD explicitly before exposing the instance beyond your own machine.

How It Works

📄 SBOM Upload

Upload a CycloneDX 1.4–1.6 or SPDX 2.3 file. Fastest path if you already generate SBOMs in your build.

🐳 Image Scan

Give it an image reference — Crane pulls it once, Syft generates the SBOM, and Gitleaks scans the same archive for secrets. Covers the OS/base-image layer.

📂 Repository Scan

Give it a Git URL — the worker clones it, runs Syft for a full application-layer SBOM, and optionally Gitleaks against the working tree.

Every finding is cross-referenced against OSV.dev, deduplicated across advisory sources (GHSA > CVE > RustSec > Go > PYSEC > OSV), and tracked over time — Celery Beat re-scans daily so newly published advisories surface automatically.

Backend API

Everything the UI does, you can do over HTTP — 85 endpoints under /api. Interactive OpenAPI docs are served by every instance at /docs. The browser uses an HttpOnly session cookie; scripts and CI use a Bearer JWT from /api/auth/login or an API token. Endpoints marked admin require an interactive admin login — API tokens can never reach user, token or global-settings management. Login and password endpoints are rate-limited per IP.

FAQ

Is SBOM-Shield really free?

Yes. Pull it from Docker Hub and run it on your own infrastructure — no accounts, no per-seat pricing, no cloud lock-in.

What SBOM formats are supported?

CycloneDX 1.4–1.6 (XML/JSON) and SPDX 2.3 (JSON) for upload. Image and repository scans generate CycloneDX SBOMs automatically via Syft.

Where does my data go?

Nowhere. SBOM-Shield is fully self-hosted — every scan, SBOM, and finding stays in your own PostgreSQL database.

Does the AI Compliance feature call an external LLM?

No. Classification and findings are entirely deterministic — pattern matching and rules against your SBOM data, with no network calls to any AI provider.

Can I run this on Kubernetes or OpenShift?

Yes — a production Helm chart ships in the repository, with non-root images that satisfy OpenShift's restricted-v2 SCC out of the box.

What do I need to run it?

Docker or Podman (or any OCI-compatible runtime). One docker compose up -d command and you're up — see Quick Start above.
